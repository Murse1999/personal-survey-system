Personal Survey System 問卷調查系統
作品介紹與現場操作講稿

==================================================
一、作品基本資料
==================================================

作品名稱：Personal Survey System
中文名稱：問卷調查系統
技術：Angular、Spring Boot、Spring Security、JWT、MySQL
前端網址：http://localhost:4200
後端網址：http://localhost:8082

作品定位：
這是一個可以讓使用者註冊、登入、建立問卷、發布問卷、填寫問卷，
並查看自己問卷統計資料的全端問卷平台。

==================================================
二、開始前準備
==================================================

開始介紹前，先確認：

1. MySQL 已啟動，personal_quiz_db 資料庫存在。
2. IntelliJ IDEA 已啟動 Spring Boot 後端，看到 port 8082。
3. 前端 Angular 已啟動，瀏覽器開啟 http://localhost:4200。
4. 先登入測試帳號，避免現場花太多時間註冊。

本機測試帳號：
Email：security-test@example.com
密碼：Abcd1234

如果登入失敗，可以改用自己目前資料庫裡已經註冊的帳號。

==================================================
三、開場介紹，約 30 秒
==================================================

【講】
我今天要介紹的是我完成的 Personal Survey System，中文是問卷調查系統。

這個作品的目標，是讓使用者可以像使用一般問卷平台一樣，
自己建立問卷、設定題目與選項、發布問卷，讓其他使用者填寫，
最後再查看統計結果。

這是一個前後端分離的全端作品：
前端使用 Angular 負責畫面和操作，
後端使用 Spring Boot 負責 API、商業邏輯和權限，
資料則存放在 MySQL。

==================================================
四、整體畫面
==================================================

【操作】
瀏覽器開啟 http://localhost:4200

【講】
這裡是問卷列表頁。

使用者可以看到目前已發布的問卷，也可以依照問卷標題、開始日期和結束日期搜尋。
列表會顯示問卷狀態，例如尚未開始、進行中和已結束。

只有進行中的問卷可以進入填寫，統計功能則會依照登入者的權限和問卷建立者判斷。
畫面右上角可以看到登入帳號，點開後可以查看自己的問卷、編輯、查看統計或刪除。

==================================================
五、介紹登入與安全性
==================================================

【操作】
點右上角帳號，或先登出，再進入登入頁。
輸入測試帳號並登入。

【講】
登入 API 驗證成功後，後端會回傳 JWT Token。
前端會把 Token 暫存在瀏覽器，之後呼叫需要登入的 API 時，
會自動在 Header 加上：

Authorization: Bearer JWT_TOKEN

後端每次收到請求時，會驗證 Token 是否有效，並從 Token 取得使用者 Email 和角色。
所以填寫問卷時，使用者的 Email 不是由前端自由輸入，
而是由後端從登入身份取得，避免使用者冒用別人的身份提交答案。

==================================================
六、建立問卷
==================================================

【操作】
回到列表頁，點選「建立問卷」。

示範輸入：
標題：面試示範問卷
說明：這是一份用來展示建立流程的問卷。
設定開始日期和結束日期。
勾選或不勾選「發布問卷」。
新增一題單選題，加入 A、B 兩個選項。

【講】
建立頁面可以設定問卷基本資料，也可以動態新增問題。
目前支援單選題、複選題和文字題。
每一題也可以設定是否為必填。

這裡的「預覽問卷」功能，可以讓建立者在真正送出前，
先確認問卷標題、題目、選項和必填設定的畫面效果。

【操作】
點「預覽問卷」，展示預覽畫面，再點「返回編輯」。

【講】
預覽只是前端畫面狀態，還沒有寫入資料庫。
確認內容後按下建立，前端才會把 JSON 請求送到 Spring Boot API。

【可選操作】
如果只是展示介面，不一定要真的建立，可以按「取消」。
如果真的建立測試問卷，展示完後可以到右上角的「我的問卷」刪除。

==================================================
七、填寫問卷
==================================================

【操作】
回到列表，點選一份目前進行中的問卷，例如「台灣天氣」。

【講】
這裡是問卷作答頁。
系統會顯示問卷開放期間，以及每一題的題型和必填狀態。

如果必填題沒有回答，前端會先提示使用者；
即使有人直接繞過前端送 API，後端也會再次檢查必填題、題目和選項，
所以真正的資料驗證是在後端完成。

【操作】
選擇一個答案，按「提交問卷」。

【講】
提交成功後，答案會寫入 quiz_response 和 response_detail。
同一個使用者對同一份問卷只能提交一次，資料庫也有唯一限制協助防止重複提交。

如果現有帳號已經填過這份問卷，請不要重複按提交，改操作統計頁即可。

==================================================
八、查看統計
==================================================

【操作】
回到列表，點右上角帳號，從「我的問卷」選擇「統計」。

【講】
統計資料只開放給問卷建立者或管理員，
一般使用者不能查看別人的填答結果。

統計頁會顯示總填答人數，
單選題和複選題會統計每個選項的人數與百分比，
文字題則會列出文字回答。

這些資料是後端依照資料庫裡的回答明細重新計算，
不是前端自己寫死的數字，所以新增填答後統計會跟著改變。

==================================================
九、我的問卷、編輯與刪除
==================================================

【操作】
點右上角 Email，展示「我的問卷」。

【講】
這裡只會列出目前登入者自己建立的問卷。
建立者可以編輯自己的問卷，也可以刪除自己的問卷。
管理員則可以管理所有問卷。

如果問卷已經有人填答，系統允許修改標題、日期和發布狀態，
但不允許直接刪除或修改題目、選項，避免舊答案找不到原本對應的題目。
如果要改變問卷結構，應該建立一份新的問卷版本。

刪除問卷時，後端會先清除回答明細和提交紀錄，
再清除題目、選項，最後刪除問卷主資料，避免資料庫外鍵錯誤。

==================================================
十、後端架構介紹
==================================================

【操作】
可以切回 IntelliJ IDEA，展示 backend/src/main/java。

【講】
後端主要分成幾個部分：

Controller：接收前端 API 請求，例如建立、修改、刪除和提交問卷。
Service：處理真正的商業邏輯，例如權限檢查、必填檢查和統計計算。
Repository：透過 Spring Data JPA 操作資料庫。
Entity：對應 MySQL 裡的資料表。
DTO：定義前後端之間傳遞的資料格式。
Config：設定 Spring Security、JWT、CORS 和密碼加密。

資料庫目前主要有六張表：
user、quiz、question、question_option、quiz_response、response_detail。

這些表透過外鍵建立關係，例如一份 quiz 有很多 question，
一次 quiz_response 又會有很多 response_detail。

==================================================
十一、前後端如何連接
==================================================

【操作】
可以展示：
src/app/core/quiz-api.service.ts
backend/src/main/java/com/example/personalproject/controller/QuizController.java

【講】
Angular 的 QuizApiService 負責呼叫後端 API，
例如 GET /api/quiz 取得問卷列表，
POST /api/quiz 建立問卷，
POST /api/quiz/{id}/submit 提交答案。

前端使用 http://localhost:8082/api 連接 Spring Boot。
後端則透過 CORS 允許 localhost:4200 的 Angular 開發伺服器呼叫。

這樣的分工讓前端負責使用者體驗，後端負責資料、規則和安全性。

十三、現場出錯時的快速處理
==================================================

1. 畫面顯示無法取得問卷：確認後端有在 8082 埠執行。
2. 登入失敗：確認帳號存在，或改用自己的測試帳號。
3. 提交顯示已提交：這是正常的防重複機制，改展示統計頁。
4. 問卷不能填寫：確認問卷已發布，而且現在在開始和結束時間內。
5. 統計不能查看：確認登入者是該問卷建立者或 ADMIN。
6. 建立測試問卷後不想保留：到右上角「我的問卷」按刪除。
